# MiniCode / codexsrc harness 源码复核

对照本地 MiniCode `82fd1f2652b9` 和 `.tmp/codex-src` `588b781ab492`。本页只看源码与本地可重复的测试，不使用 SWE-bench 分数推断架构优劣，也没有访问外网。

## 本轮补齐

- `agent.code_mode_only` 现在默认开启；配置为 `false` 可使用直接工具模式。模型请求只展示编排、提问、搜索和计划入口，普通工具保留在 `tool_exec` 内，权限、工作区和会话限制不变。
- `tool_exec` 的模型说明按当前权限生成精简内部工具目录，包含工具名、必需参数、常用可选参数和简短用途；复杂参数可从 `ALL_TOOLS` 查询。禁用的工具不写入目录。Codexsrc 的代码模式同样把内部工具说明放在 `exec` 描述中。
- `tool_exec` 和 `tool_wait` 默认等待从 1 秒调为 10 秒；调用方仍可显式缩短。Codexsrc 的同类默认值为 10 秒。
- 没有 `tool_exec` 的 SDK 自定义注册表继续直接展示其工具；扩展显式选择工具时尊重该选择。会话初始化把默认会话策略与当轮展示策略分开存储，避免之后切换设置时误把旧展示策略当成永久限制。
- 模型元数据可声明 `tool_mode: direct | code_mode | code_mode_only`，优先于 `agent.code_mode_only` 默认值。Provider 设置界面按模型保存该字段；模型在会话中切换时下一轮重新生成工具表面。`direct` 不展示新的 `tool_exec`，但保留 `tool_wait` 以便已启动的代码单元收尾。
- 工具元数据现支持直接展示、延迟发现、仅模型直接调用、延迟后仅模型直接调用、仅代码模式调用、隐藏六种表面。提问和计划控制工具归为仅模型直接调用，内部目录与权限检查使用同一表面判定。

同一套本地内置工具注册表中，`direct` 为 50 个、46,423 字符，`code_mode` 为 51 个、49,446 字符，默认 `code_mode_only` 为 7 个、20,218 字符。这是 schema 文本的本地测量，不代表 token 费用、模型能力或端到端时延已经改善。当前配置加载的 `agent.code_mode_only` 为 `true`。

## 后续链路修复（同日）

- 项目指南和路径匹配规则现在作为 user 消息放在当前请求历史之前；稳定 system prompt、工具 developer 说明与项目规则分层。提示词摘要继续记录规则来源与哈希。
- MCP 工具默认超时改为 300 秒，服务器显式设置的 `tool_timeout_sec` 仍优先。
- `read_mcp_resource` 必须指定服务器和 URI，不再依连接顺序读取同名 URI。资源和资源模板目录支持按服务器传入 cursor 逐页读取。
- MCP 二进制资源保留 MIME、URI 和 base64 artifact 引用，不再只返回“binary resource”占位文字。MCP 工具结果原有图片、音频与结构化内容处理保留。
- Skill 激活时检查声明的 MCP 服务器是否已连接；缺失时向用户发通知，并在模型可见的 skill 内容中标明。安装流程见下方续补。
- `edit_file` 对相同旧、新文本的无操作调用先检查目标路径、文件内容和预期哈希；不存在的文件或文本会报错，真实无操作仍成功。

这些修复由本地回归用例验证；尚无同模型同任务的端到端对照数据，因此不据此声称解题率或费用提升。

## 第二轮链路修复

- MCP 注册时遵守 `_meta.ui.visibility`：仅供界面使用的工具不进入模型目录，未声明可见性的普通工具仍保持可用。
- MCP 工具返回的 `resource_link` 保留名称和 URI，模型可据此继续读取资源。
- MCP 二进制资源改走 artifact ID、MIME 和字节数通路，不再把 artifact 引用误写成工作区路径型 `output_files`；原始内容经会话归属校验后可预览或下载，多个资源各有预览事件。
- 默认 `code_mode_only` 下，`tool_search` 明确提示发现后的工具应通过 `tool_exec` 调用。
- 模型读取 `SKILL.md`，或本地 shell 明确读取该文件、运行其 `scripts/` 下的脚本时，记录隐式 skill 使用并检查 MCP 依赖。动态拼接、无法静态解析的 shell 命令不据此猜测 skill 使用。
- 模型元数据未声明 `tool_mode` 时，模式选择继续读取显式 adapter/config 设置，而不是直接回落到全局默认。

这些是源码契约修复，未运行真实模型评测。

## Skill MCP 依赖安装续补

`agents/openai.yaml` 中的 MCP 依赖现在保留 `transport`、`url`、`command` 和 OAuth 回调端口。显式激活 skill 时，若依赖未配置且元数据足够，桌面端先展示要安装的服务器及地址或命令；用户选择安装后，通过既有 MCP 配置校验、管理策略、配置变更 hook 和原子写入入口一次保存，并重新加载连接。已有同名服务器不会被覆盖；缺少连接参数、被策略禁止或连接失败的依赖仍会向用户和模型明确显示为不可用。没有可交互确认通道的 SDK 调用只提示，不会静默安装。隐式读取 skill 仍只登记使用和提示依赖，不触发安装。

## 逐环节差距

| 环节 | 源码结论 | 后续判断 |
| --- | --- | --- |
| 模型配置 | Codexsrc 的模型元数据含 `tool_mode`；MiniCode 已支持同名的三种模式，模型声明优先，全局 `agent.code_mode_only=true` 作为未声明模型的默认。 | **源码能力已对齐**。本地小模型的实际行为仍需验证；未知声明按 Codexsrc 方式视为未声明，不新增自动降级。 |
| 提示词与工具发现 | Codexsrc 在 `exec` 说明中渲染内部工具定义；MiniCode 本轮新增精简目录，完整 schema 留在 `ALL_TOOLS`。 | 完整参数类型没有全部前置；复杂工具可能仍需一次查询。保持精简是刻意的请求大小取舍，需真实模型验证。 |
| 工具展示与执行 | MiniCode 已增加与 Codexsrc 对应的逐工具模型/内部暴露维度，并在模型 schema、延迟目录和内部执行边界共用判定。 | **源码能力已对齐**。保留 MiniCode 的 `core` 旧名称及现有权限契约；没有为名称统一重写工具注册表。 |
| 权限与并行 | MiniCode 内部调用仍走 `ToolBatchRunner`、权限检查和相邻安全工具并行；Codexsrc 按工具并行能力使用读写准入。 | 两边都有核心机制。本轮本地测试覆盖内部调用、延迟工具激活和写入审批，不能仅从源码推断吞吐优势。 |
| Shell 调度 | Codexsrc 的 `exec_command` 声明支持并行调用。MiniCode 刻意将所有 `run_command` 当成不可证明只读的 shell，连 `git status` 也不进入安全并行批次。 | **明确策略差异**，但并发执行任意 shell 命令可能有副作用；没有受影响任务的证据前不放松权限与顺序。独立读取优先使用已有的类型化文件/搜索工具。 |
| Provider、上下文、压缩与恢复 | MiniCode 已有请求重试、稳定提示词/工具 schema、上下文压缩和完整检查点；此前发现的恢复截断问题已修。 | 没有发现可复现的新核心缺口。不同协议的缓存字段和费用单位不能直接比较。 |
| 用户交互与终态 | 提问和计划控制工具在代码模式仍直接可见；运行终态与任务正确性在两边都是不同概念。 | 没有同任务、同模型的对照运行，不能给 codexsrc 或 MiniCode 归因解题率差异。 |

工具策略、代码编排、模型实时切换、提供商元数据、模型注册及配置关联测试通过；前端按模型保存设置的用例通过，TypeScript 检查通过。真实模型在默认代码模式下的质量、延迟和缓存效果尚未测试。本轮没有启动新评测。
