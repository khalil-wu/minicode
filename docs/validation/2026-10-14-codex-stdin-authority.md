- `core/src/guardian/approval_request.rs:156,289,388`: measure the complete sorted Guardian JSON action, including the globally inserted `environment_id`, plus the complete approval reason against 8,000 UTF-8 bytes. - `core/src/tools/approvals.rs:174,733`: `PermissionRequest` sees `session_id`, `chars`, `parent_call_id`, `approval_id`, environment, launch cwd, tty, sandbox intent, and agent grants. The manual display uses the complete shell-quoted `write_stdin --session-id … INPUT` action. Input approvals cannot edit arguments, persist a session approval, or borrow another request digest. Permission hooks, the shared Guardian service, and the existing owner-bound approval waiter form one path.
- `core/src/tools/handlers/unified_exec.rs:67`, `unified_exec/process_manager.rs:1012`: this checkout defaults nonempty stdin yield to **250 ms**, clamps it to 250–30,000 ms, and gives tty writes a 100 ms reaction window. Empty polls wait at least 5,000 ms and use `background_terminal_max_timeout` (default 300,000 ms). Existing MiniCode status calls retain their default immediate snapshot. Empty input and non-tty pure Ctrl-C skip review. Windows pipe Ctrl-C kills the exact owned tree, matching `utils/pty/src/pipe.rs`; Unix uses that process group's SIGINT.
- `core/src/tools/handlers/unified_exec/write_stdin.rs:144`, `tools/context.rs:409`: stdin/status is transport and does not run another Bash PreToolUse. Every Monitor transport result suppresses a generic Monitor PostToolUse. A final normal process result claims exactly one original Bash PostToolUse with the original execution ID, raw command input, and bounded raw output. Polling a running process and replaying completed output do not claim another completion.
- `tools/context.rs:409,413`: a command that completed with a nonzero exit code is still a successful execution tool result. MiniCode preserves its real process status, exit code and stderr while returning `is_error=False`/tool status `success`; `store_result` therefore avoids inventing an execution error or retry instruction. Sandbox setup failures, timeouts, cancellation, output persistence errors, and actual execution errors keep their failure evidence. `SandboxResult.execution_error` now distinguishes an OS launch/I/O error from a normal command exit, so exit 127 alone does not decide the harness result.

`monitor(action='write_stdin')` now returns current command output/status/cursors after writing, including when the caller omitted explicit yield/cursor arguments. The old `Wrote N bytes` observation no longer replaces the process result; byte count and explicit MiniCode `close_stdin` remain host metadata. Existing ordinary pipe input is retained as an established MiniCode function even though Source restricts non-tty sessions to empty polls/Ctrl-C.
