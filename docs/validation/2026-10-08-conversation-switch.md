# 会话切换修复与验证（2026-10-08）

依据用户实际 Windows 桌面日志、原发布包与原会话存储的独立副本排查。原日志记录了连续多次切换；原包实机复现首次切换期间约 6–8 秒没有可见消息，加载状态只有 `sr-only` 文本。快速 A→B→A 最后能到达 A，没有据此把有限加载时间认定为永久死锁。

## 修复

- 将既有加载状态显示为灰色短行与小图标，复用现有字体、动画和减少动态效果设置。
- 切换错误与拒绝 ACK 按目标会话结束等待，保留源会话消息、未发送草稿和其他会话的导航选择；显示真实错误。
- 命令结果同时保留顶层与 `data` 的明确归属，优先使用 producer 指定值，其次是入口捕获的命令 owner；明确的空工作区不回填旧目录。
- 无效或未信任工作区，以及生命周期入口准备 owner 时的读取错误，都按实际目标和请求命令报告失败；不忽略目录问题继续执行。
- 首个公开历史事件使用已有轻量会话快照，完整能力信息保留在上下文恢复完成帧；协议回归要求公开历史先于完整能力汇总。实机结果未证明端到端速度改善，不据此宣称秒开。
- 恢复会话与扩展目录刷新只投影模型元数据，不重新构建客户端；当前界面的能力与工具模式来自当前选择，执行继续使用对应回合的模型快照。退役 provider 保留原标识与历史，明确其目录和传输能力不可用，真正执行时按既有 `model` 错误分类拒绝；显式模型与强度修改保留实际绑定契约。

上述错误分支通过真实协议 dispatch 回归核对，不将其冒充为此次本机日志中已经出现的错误。原包本机复现没有持续挂起、模型异常或 renderer page error；确定的界面问题是等待时整块空白。
