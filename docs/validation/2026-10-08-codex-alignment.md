# 对话投影、权限与浏览器链验收（2026-10-08—09）

本批以本机 Codex 参考图册、用户补充的审批与加载截图，以及 `.tmp/codex-src` 的工具生命周期、子任务权限和会话批准契约为依据。编辑器继续沿用既有 Cursor 方向，本批不改用户工作区文件和未保存内容。

## 修复的真实根因

- 只读子任务曾把父任务的完全访问权限错误改成 Plan，导致网页读取反复审批。现在继承真实父权限；明确的只读、禁止写入和作用范围仍在执行时生效。
- 最后核对真实天气任务发现探索角色与 teammate 仍有同类分支。已统一所有角色的默认权限来源，teammate 刷新不再伪造父权限；只读角色的执行合同集中到同一入口，显式 required-plan 批准仍保留。
- 普通并行任务未声明 `write_scope` 曾被一律视为冲突的写入者，天气查询在启动前就被拒绝。移除该额外门槛；不根据任务标题猜测权限，保留明确声明的范围冲突检查。
- 权限切换与提交消息之间存在时序竞争。提交现在等待权限命令的语义确认，旧会话事件不会改变新会话权限，已保存会话不再被前端旧值覆盖。切换期间保留输入框外形和草稿，暂停交互及发送。
- 工具准备、等待批准曾被投成运行状态。短行、状态图标、Inspector 与导出现在区分准备、审批、实际执行和终态。侧栏运行圈只来自真实任务；会话加载在消息区中央显示。
- 浏览器结果之外曾额外拼出说明和“下一步”提示；执行包装和智能体轮询又重复占用主过程区。现在保留实际动作及可展开的真实错误，按真实调用关联去除重复包装，完整原始记录仍在 Inspector。
- 内置浏览器已经通过当前预览授权后，桌面端还会再次弹出本机网络确认。现有授权沿后台专用令牌传到同一原生视图；手动导航、跨来源与取消边界保持独立。工具请求通过当前会话右侧浏览器取得真实视口和绘制帧，后台会话不抢前台。
- Mermaid 不支持暗色主题的 OKLCH 颜色。现在转换为可解析颜色，保留完整 SVG 尺寸与可拖动滚动条。中英文界面、正文和过程摘要统一字体；代码正文仍采用代码字体。
- 真实浏览器截图已保存，但 Markdown 默认过滤器删除了 `artifact://`，造成“本地图片不可用”。现在使用消息所有者和当前连接解析产物；代码工具转发图片复用原产物身份，正文已嵌入的同一图片不再重复显示。

## 界面核对

审批改为单层圆角卡、灰色权限标识、具体操作及原因，底部为拒绝、允许一次和范围下拉。“允许此次对话”接通现有会话批准机制，不是全局放行。审批占据底部输入区；处理后恢复原输入框与草稿。文件、命令、下拉和 390px 宽度的亮暗截图均已检查，无溢出或裁切。

上传的图片缩略图与文件位于消息文字上方。新一轮回复按真实可用高度保留空间，用户向上阅读后停止跟随。“已处理”时长每秒更新，位于过程顶部细分隔线上方；最终答案完整到达后按正常模式收起过程，保留用户主动展开的选择。
