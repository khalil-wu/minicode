## 前后端接线：已检查的依据与剩余工作

### 1. 协作启动不是子任务完成

Codex 在 core/src/tools/handlers/multi_agents/spawn.rs 中先发 InProgress，实际 spawn 成功后才带接收 thread、nickname/role 与 agents_states 完成协作调用；spawn 请求完成不等于子 agent 工作结束。

MiniCode 的链路为 TaskTool → SubagentLifecycle/AgentRuntime → subagent 状态/转录及 tool result delegations → public_projection → runtimeEvents/sessionEvents/transcriptHydration → chatSurfaceState → CollaborationCell/SubagentsTab/ChatTurn。

已具备：delegations 的 started_at 过滤、失败请求不虚构启动、独立子任务工作记录、不显示主用户“我”的派遣气泡。相关后端与前端测试本轮通过。

需要继续统一：TaskTool._delegation_record 使用 teammate_name 或 task_id/subagent_id；普通路径也有以 agent_type 填 teammate_name 的情况。应让后端登记的真实显示名成为共同来源，前端不靠长派遣说明或 ID 猜名称。delegations 当前没有 agent_path，而头像优先取 agentPath；需验收启动回执先于完整状态的顺序，确保头像和名称不会改变。此项属于源码确定的待核对契约，不冒充已录到的运行故障。

### 2. 代码执行包装仍落入普通过程

当前真实历史的展开截图包含多条“● 运行”，网页读取/搜索已经另有自己的真实操作行。backend/tools/code_execution.py 的 ToolExecTool/ToolWaitTool 沿用 BaseTool 的 timeline 投影，tool_projection/tool_events 带入前端；ActivityCell 对有输出的 code-mode record 保留了“运行”外层。

应从事件与投影关系区分组合包装、真实内部操作、独立输出/图片和实际失败。内部包装不作为正常操作行重复显示；仍要保留独立用户结果、真实失败及原始诊断记录。不能只用 CSS 隐藏全部 tool_exec 输出，也不能重命名为“运行”就算对齐。

### 3. 结束与阅读偏好

projectChatTurnToAgentLoop 区分完整 final answer、流式 tail 和 interrupted/failed。AgentTurn 用阅读偏好处理完成时折叠，ChatTurn 在子任务转录模式清除派遣 userCell；这些结构应保留。测试不等于对每种真实运行状态的视觉验收。

### 4. 审批、范围和 owner

审批直接替换输入区，处理后恢复草稿/附件，来源和返回目标必须贯穿事件、请求、确认和反馈。Diff/文档/网页/子任务不要根据当前激活聊天猜 owner。另一聊天正修改切换、侧栏和浏览器的这部分实现，本报告绑定 r6 及审计时的源码，后续构建需复看。
