# MiniCode 架构选择：Web 端 vs 桌面端

## 核心结论：**保留 Web 端，可选桌面端包装**

---

## 架构对比

### 当前 MiniCode 架构

```
┌─────────────────────────────────────────┐
│         MiniCode (Web First)            │
├─────────────────────────────────────────┤
│  Frontend (React + Vite)                │

│    - MCP/Skills 集成                    │
└─────────────────────────────────────────┘
```


## 差异分析

| 维度 | MiniCode (Web) | Claude Code (CLI) | 差异大小 |
|------|----------------|-------------------|---------|
| **UI 渲染** | 浏览器 (React DOM) | 终端 (Ink TUI) | ⭐⭐⭐⭐⭐ 巨大 |
| **交互方式** | 鼠标点击 + 键盘 | 纯键盘 | ⭐⭐⭐⭐ 很大 |
| **部署方式** | Web 服务器 | 本地可执行文件 | ⭐⭐⭐⭐ 很大 |
| **文件访问** | 通过 API | 直接文件系统 | ⭐⭐⭐ 中等 |
| **可视化能力** | 强（图表/图片/富文本） | 弱（纯文本） | ⭐⭐⭐⭐⭐ 巨大 |
| **多用户支持** | 天然支持 | 单用户 | ⭐⭐⭐⭐ 很大 |
| **核心逻辑** | Agent Loop + 工具 | Agent Loop + 工具 | ⭐ 很小 |

## 为什么保留 Web 端？

### 1. **你的架构已经是 Web First**

```python
# backend/main.py
app = FastAPI(...)  # Web 服务器
app.mount("/assets", StaticFiles(...))  # 静态资源
@app.websocket("/ws")  # WebSocket 通信
```

**改成 CLI 需要**:
- ❌ 重写整个前端（React DOM → Ink TUI）
- ❌ 重写通信层（WebSocket → 进程内调用）
- ❌ 重写部署方式（Web 服务器 → 可执行文件）
- ❌ 失去可视化能力（图表、图片、富文本）

**成本**: 🔥🔥🔥🔥🔥 极高（几乎重写）

### 2. **Web 端的独特优势**

#### ✅ 可视化能力强
```tsx
// 可以展示
- 代码高亮和语法着色
- Diff 对比视图
- 图表和数据可视化
- 图片预览
- Markdown 富文本渲染
```

#### ✅ 交互体验好
```tsx
// 鼠标 + 键盘
- 点击按钮
- 拖拽文件
- 滚动查看长内容
- 多窗口/标签页
```

#### ✅ 易于调试和迭代
```bash
# 开发模式
npm run dev  # 热重载
# 浏览器 DevTools
```

#### ✅ 多用户/远程访问
```bash
# 可以部署到服务器
# 团队成员通过浏览器访问
http://your-server:8000
```

### 3. **Claude Code 选择 CLI 的原因（不适用于你）**

| Claude Code 的需求 | MiniCode 的情况 |
|-------------------|----------------|
| 集成到开发者工作流（命令行） | ✅ Web 也可以（浏览器标签） |
| 快速启动（`claude` 命令） | ✅ 可以用 Tauri 包装 |
| 本地文件系统访问 | ✅ 已通过 API 实现 |
| 轻量级（无浏览器依赖） | ❌ 你的目标是学习，不是极致轻量 |
| 终端用户习惯 | ❌ 你的用户可能更习惯 GUI |

## 推荐方案：Web + 可选桌面包装

### 方案 A: 纯 Web（推荐）

**保持现状**，继续优化 Web 端：

```
用户 → 浏览器 (localhost:8000) → FastAPI → Agent
```

**优势**:
- ✅ 无需重写
- ✅ 可视化能力强
- ✅ 易于调试
- ✅ 可部署到服务器

**劣势**:
- ❌ 需要浏览器
- ❌ 不能离线使用（需要后端运行）

### 方案 B: Web + Tauri 桌面包装（最佳）

使用 **Tauri** 将 Web 端打包成桌面应用：

```
┌─────────────────────────────────────┐
│   Tauri Desktop App (可选)          │
│   ┌─────────────────────────────┐   │
│   │  WebView (你的 React 前端)  │   │
│   └─────────────────────────────┘   │
│   ┌─────────────────────────────┐   │
│   │  Rust Backend (Tauri)       │   │
│   │  ↓ 调用                     │   │
│   │  Python Backend (FastAPI)   │   │
│   └─────────────────────────────┘   │
└─────────────────────────────────────┘
```

**实现成本**: ⭐⭐ 低（只需配置 Tauri）

**步骤**:
```bash
# 1. 安装 Tauri
npm install -D @tauri-apps/cli

# 2. 初始化
npx tauri init

# 3. 配置 tauri.conf.json
{
  "build": {
    "beforeDevCommand": "npm run dev",
    "beforeBuildCommand": "npm run build",
    "devPath": "http://localhost:5173",
    "distDir": "../frontend/dist"
  }
}

# 4. 打包
npm run tauri build
```

**优势**:
- ✅ 保留所有 Web 端优势
- ✅ 原生桌面应用体验
- ✅ 系统托盘、快捷键
- ✅ 自动更新
- ✅ 跨平台（Windows/Mac/Linux）
- ✅ 比 Electron 更轻量（Rust + WebView）

**劣势**:
- ⚠️ 需要学习 Tauri（但很简单）
- ⚠️ 增加打包复杂度

### 方案 C: 改成 CLI（不推荐）

**完全重写**成 Claude Code 风格：

```
用户 → 终端 → Node.js CLI → Agent
```

**成本**: 🔥🔥🔥🔥🔥 极高
- 重写前端（React DOM → Ink TUI）
- 重写通信层
- 失去可视化能力

**不推荐理由**:
- ❌ 成本太高
- ❌ 失去 Web 优势
- ❌ 你的架构已经是 Web

## 具体建议

### 短期（当前阶段）

**保持 Web 端**，继续完善功能：

```bash
# 启动方式
python -m backend  # 后端
npm run dev        # 前端

# 访问
http://localhost:8000
```

**专注于**:
1. ✅ 完善核心功能（已完成大部分）
2. ✅ 优化 UI/UX
3. ✅ 添加更多工具（LSP、WebSearch）
4. ✅ 对话存储优化

### 中期（功能稳定后）

**添加 Tauri 桌面包装**（可选）：

```bash
# 用户可以选择
1. Web 版: 浏览器访问
2. 桌面版: 下载 .exe/.dmg/.AppImage
```

**优势**:
- 两种使用方式
- 代码复用（同一套前端）
- 满足不同用户需求

### 长期（如果需要）

**考虑 Electron**（如果 Tauri 不够）：

```bash
# Electron 更成熟，但更重
npm install electron
```

## 最终建议

### 🎯 推荐方案：**Web First + Tauri 可选**

1. **现在**: 保持 Web 端，继续完善功能
2. **稍后**: 添加 Tauri 桌面包装（1-2 天工作量）
3. **结果**:
   - Web 版：浏览器访问，易于开发和调试
   - 桌面版：原生应用，更好的用户体验

### 为什么不改成 CLI？

| 原因 | 说明 |
|------|------|
| **成本太高** | 需要重写 80% 的代码 |
| **失去优势** | 可视化、交互体验、多用户 |
| **不符合目标** | 你的目标是学习 AI Agent，不是做 CLI 工具 |
| **架构已定** | FastAPI + React 已经很成熟 |

### 核心逻辑是通用的

**好消息**: Agent Loop、工具系统、权限检查等核心逻辑是**通用的**，无论 Web 还是 CLI 都一样：

```python
# 这些代码在 Web 和 CLI 中都一样
backend/agent/loop.py       # Agent Loop
backend/tools/              # 工具系统
backend/permissions/        # 权限检查
backend/workspace/          # 项目上下文
```

**只有 UI 层不同**:
- Web: React + WebSocket
- CLI: Ink + 进程内调用

---

## 总结

**保留 Web 端**，因为：
1. ✅ 你的架构已经是 Web First
2. ✅ 可视化能力强
3. ✅ 易于开发和调试
4. ✅ 可以用 Tauri 包装成桌面应用
5. ✅ 核心逻辑（Agent/工具/权限）是通用的

**不要改成 CLI**，因为：
1. ❌ 成本极高（重写 80% 代码）
2. ❌ 失去可视化优势
3. ❌ 不符合你的学习目标
4. ❌ Web 端已经很好了

**最佳路径**: Web → Web + Tauri → 完善功能
