本报告固定使用 `opus48-full-20260925` 的前 231 题；其中 227 题已由 SWE-bench 官方 evaluator 评分，183 题 resolved。前 130 题运行 MiniCode `6e766ae5`，后 101 题运行 `25f199e5`。项目分布随题序变化，混合分数不能当作单一源码版本成绩，也不能用两个阶段的原始通过率推断代码改动效果。本地 codexsrc 快照为 `588b781ab492`，尚无同模型、同题、同预算的 Codexsrc 跑分。

## 已完成的工具表面改动

Codexsrc 的 `ToolExposure` 区分直接展示、延迟发现、仅代码模式等表面；其 `CodeModeOnly` 可隐藏普通工具的直接 schema，同时保留代码编排中的调用。MiniCode 原有 `core/deferred/hidden` 与会话工具选择共用同一可用性过滤器：仅选中 `tool_exec/tool_wait` 时，编排内部的 `read_file` 也会变为不可用。

`agent.code_mode_only` 现在默认启用，将直接展示与内部执行分开。模型直接收到 `tool_exec`、`tool_wait`、`tool_search`、`ask_user` 和计划控制工具；内部仍按原有会话、权限、工作区和工具禁用规则调用其他工具。需要旧直接工具模式时，配置文件可写 `"agent": {"code_mode_only": false}`；评测入口可设置 `MINICODE_EVAL_CODE_MODE_ONLY=0`。默认行为的质量与延迟仍需要同题 A/B 验证。

代码模式默认开启后，`tool_exec` 的说明里还会按当前权限列出内部工具的精简名称、参数和用途；复杂工具的完整 schema 仍可从 `ALL_TOOLS` 查阅，避免首轮只能盲猜工具名。本地同一内置注册表的 schema 从 51 个、49,446 字符降到 7 个、20,218 字符。最终关联测试 64 项通过。此结果仅证明 schema 缩减和调用边界正确；模型成功率、费用与延迟收益尚未实测。

## 后续验证顺序

1. 用少量相同题目对比直接工具模式与 `code_mode_only`，同时记录 resolved、模型请求数、工具批次、首工具时延、输入 token 和缓存字段覆盖率；不把 schema 缩减直接当成质量提升。
2. 让提交补丁只包含任务修改；官方测试补丁应用失败时单列评分异常，保留原始报告供审计。
3. 对依赖外部 HTTP 的题目检查无补丁基线并提供稳定测试服务；在此之前不调整官方 183/227 的已记录分数。
