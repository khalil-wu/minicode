# Memory versions

`memories.version` selects `v1` or `v2`. An explicit selection wins. When memory is enabled without a version selection, a fresh profile starts on V2 if it has no V1 memory directory. Existing profiles keep V1. Setting `memories.dual_write = false` explicitly also preserves the V1 default for a fresh profile.

V1 uses the existing `data/memory` workspace. V2 uses its sibling `data/memory_v2` workspace. Both retain MiniCode's project scope and shared-worktree identity. Their generated files, jobs, claims and SQLite state are independent. Reading one version never falls back to the other version.

While V1 is selected, `memories.dual_write = true` runs both generation pipelines in the background. Once V2 is selected, only V2 generation runs. A loaded conversation retains its selected memory version for the lifetime of its runtime, including later configuration updates, so its injected summary and retrieval tools use the same namespace.

V2 extraction emits `rollout_summary` and `rollout_slug`. Its bounded evidence gives priority to human input, answers with their original questions, final answers, other-agent messages, commentary, harness context, then tool records. Selected evidence remains in chronological order. Media payloads and loaded instruction documents are excluded from extraction. V2 consolidation produces `memory_summary.md`; it does not require `MEMORY.md` or `raw_memories.md`.

The summary begins with `v1` (the artifact format marker), even when generated by V2. A V2 summary must be under 10,000 UTF-8 bytes and include `## User Profile`, `## User preferences`, `## General Tips`, and `## What's in Memory`.

The existing WebSocket command transport exposes `thread/memory/read` with `threadId` and `memory/status` with optional `minConsolidatedThreads` (default 20, range 1-4096). Results arrive in `command.result.data`: `summary` for the thread read, and `v2Ready`/`v2ConsolidatedThreads` for status. These methods use the existing MiniCode transport envelope; JSON-RPC app-server compatibility is a separate interface.

Host memory reset covers both existing version workspaces. Forgetting a thread removes its generated database records from both versions, including when generation is disabled or no model is available; consolidation runs when a model is available.
